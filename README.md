# synthetic-rt-reports-fr

Synthetic French breast cancer radiotherapy follow-up reports generated with a Context-Augmented Generation (CAG) pipeline. Eleven open-source LLMs are compared across combinations of dataset, prompt strategy, and sampling temperature, producing a reproducibility-oriented evaluation campaign.

The campaign ran across **two HPC clusters** with complementary GPU resources:
- **LIG OAR cluster** (`aker.imag.fr`) — 7 small-to-mid models (7B–32B) on NVIDIA A6000
- **Jean Zay (IDRIS)** — 4 heavy models (8B–70B, medical domain) on NVIDIA V100

> **Data privacy notice.** The preprocessed patient profiles (`data/`, `data_processed/`) are derived from publicly available datasets (see below) but are **not included in this repository**. Real clinical reports (`data/CR_reels/`) must never be published. Only generated outputs and evaluation results are committed.

**Experimental grid** — 132 combinations total:  
11 models × 2 datasets (METABRIC, SEER) × 2 prompts (0-shot, 5-shot) × 3 sampling presets (conservateur/standard/exploratoire) × 700 reports per combination

| exploratoire   | 0.8         | 0.95  | 1.15               |

## Automatic evaluation metrics

**Per report:** word count, MSTTR-100 (lexical richness), Flesch Reading Ease (FR), Gunning Fog (FR), perplexity (`asi/gpt-fr-cased-base`), BERTScore-max vs. 5-shot reference reports.

**Per group:** Self-BLEU-4, Distinct-1/2, mean pairwise cosine similarity (TF-IDF).

**BERTScore encoders:** CamemBERT-base, CamemBERT-bio, DrBERT — computed via `add_bertscore_encoder.py`.

> Flesch RE and Gunning Fog use a native French syllable-counting implementation (vowel-group heuristic, Kandel & Moles 1958) — no `textstat` dependency.

## Reproducing the pipeline

### Prerequisites

```bash
pip install transformers torch pandas faker sacrebleu bert-score scikit-learn
# Python 3.10+, CUDA 11.8+ for GPU inference
```

### 1 — Download and preprocess patient data

**METABRIC** — download the clinical data CSV from [cBioPortal](https://www.cbioportal.org/study/clinicalData?id=brca_metabric) and place it in `data/`.

**SEER** — download the breast cancer dataset from [IEEE DataPort](https://ieee-dataport.org/open-access/seer-breast-cancer-data) and place it in `data/`.

```bash
python scripts/preprocess_metabric.py
python scripts/preprocess_seer.py
# → data_processed/metabric_preprocessed.csv
# → data_processed/seer_preprocessed.csv
```

### 2 — Smoke-test locally (CPU, tiny model)

```bash
python scripts/generate_cag.py \
    --dataset metabric --prompt_type 0shot \
    --model Qwen/Qwen2.5-0.5B-Instruct \
    --n 5 --out outputs/smoketest.jsonl
```

### 3a — Generate the full campaign on the LIG OAR cluster

```bash
# From the LIG cluster frontend (aker.imag.fr)
python scripts/oar-cluster/make_jobs.py    # generates logs/jobscripts/
bash jobs/oar-cluster/submit_all.sh        # submits all OAR jobs (generation + evaluation chained)
```

### 3b — Generate the full campaign on Jean Zay (IDRIS)

```bash
# From the Jean Zay login node
# 1. Download models to $SCRATCH/hf_cache (once)
bash jobs/jean-zay/download_models.sh
bash jobs/jean-zay/download_eval_models.sh

# 2. Generate job scripts and submit
python scripts/jean-zay/make_jobs.py       # generates $SCRATCH/CAG_slurm/jobscripts/
bash jobs/jean-zay/submit_jeanzay.sh       # submits all SLURM jobs

# 3. If some jobs failed or were interrupted, re-submit intelligently
python scripts/jean-zay/make_resubmit.py   # scans outputs, skips complete, continues partial
bash $SCRATCH/CAG_slurm/resubmit_jeanzay.sh
```

> **Jean Zay environment:** use `module load pytorch-gpu/py3/2.7.0`. The `$SCRATCH` filesystem holds model weights and outputs (not tracked by git). See `scripts/jean-zay/campaign_config.py` for partition and QOS configuration.

### 4 — Evaluate manually (single model, any cluster)

```bash
# OAR cluster
python scripts/oar-cluster/evaluate_synthetic_reports.py \
    --input outputs/generated_CR/qwen7b/*.jsonl \
    --out_per_cr  outputs/metrics_results/qwen7b/qwen7b_eval_per_cr.csv \
    --out_summary outputs/metrics_results/qwen7b/qwen7b_eval_summary.csv

# Jean Zay
python scripts/jean-zay/evaluate_synthetic_reports.py \
    --input $SCRATCH/CAG_outputs/apertus70b_*.jsonl \
    --out_per_cr  $SCRATCH/CAG_outputs/apertus70b_eval_per_cr.csv \
    --out_summary $SCRATCH/CAG_outputs/apertus70b_eval_summary.csv
```

### 5 — Add a BERTScore encoder

```bash
bash jobs/oar-cluster/submit_bertscore.sh
# or directly: edit jobs/oar-cluster/bertscore_config.sh, then run add_bertscore_encoder.py
```

### 6 — Summarize results across all models

```bash
python scripts/summarize_lexical_metrics.py   # → outputs/metrics_results/lexical_metrics_by_temperature.csv
python scripts/summarize_bertscore.py         # → outputs/metrics_results/bertscore_by_model.csv
```

## Cluster notes

### LIG OAR cluster

- Frontend: `aker.imag.fr`
- GPU nodes: `lig-gpu8.imag.fr`, `lig-gpu10.imag.fr` (NVIDIA A6000, 48 GB each)
- Job syntax: `/gpu=N`, walltime ceiling: 100 h
- Pascal-architecture nodes (gpu1–gpu5) are **not compatible** with recent model dtypes

### Jean Zay (IDRIS)

- Account: `bbo@v100`, project `bbo`
- Partitions used: `gpu_p13` (V100 16 GB × 4/node) for 8B models, `gpu_p2` (V100 32 GB × 8/node) for 70B models
- QOS: `qos_gpu-t3` (≤ 20 h) for 8B, `qos_gpu-t4` (≤ 100 h) for 70B
- Model weights and outputs stored in `$SCRATCH` (not committed to git)
- Offline inference: set `TRANSFORMERS_OFFLINE=1` and `HF_DATASETS_OFFLINE=1`
